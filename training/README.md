# chess-ai training rig

Python/PyTorch training pipeline for the `ai-chess` browser app.

The browser app owns inference and UI. This directory owns *training*:

- a faithful Python port of the browser's `ChessEngine.ts`
- PyTorch ResNet (with SE blocks + WDL head) mirroring `ChessNet.ts`
- self-play workers + MCTS
- a weight exporter that emits `SerializedWeights` JSON the browser loads as-is

## Layout

```
training/
├── pyproject.toml
├── src/chess_ai/
│   ├── engine.py        # Board, Move, legal-move generation, apply_move
│   ├── encoding.py      # encode_board (20 planes), move_to_index
│   └── ...              # (PyTorch model, MCTS, self-play added in later phases)
└── tests/
    ├── test_parity.py   # Byte-parity vs a TS-engine-generated fixture
    └── fixtures/
        └── parity_positions.json   # Generated by `scripts/dump_parity.ts`
```

## Getting started

```bash
cd training
python -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'
```

Install PyTorch separately for your accelerator (CUDA / MPS / CPU):
<https://pytorch.org/get-started/locally/>.

## Parity test

The parity test is the foundation for every downstream phase. Before training
anything, prove that the Python engine and encoder produce byte-identical
outputs to the TS side for the same positions.

```bash
# From the project root (Node side):
npm run dump-parity       # writes training/tests/fixtures/parity_positions.json

# From training/:
pytest -v                  # runs the parity test against that fixture
```
